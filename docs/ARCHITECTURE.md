# 架构与实现说明

本文记录圆锥截面实验室的核心设计，重点是「点选保留部分」的分块系统——它是最复杂、也最容易出 bug 的部分。

---

## 一、整体结构

整个应用是**一个 HTML 文件**（`src/index.html`）：

```
<style>   ... 全部 CSS
<body>    ... 全部 DOM 骨架
<script>  一段 IIFE，包含全部逻辑
  (function(){ "use strict";
     ... 变量与函数全是闭包内局部变量
  })();
```

**注意**：脚本包在 IIFE 里，所有变量都是**闭包局部变量**，不会泄漏到 `window`。
写测试钩子时必须把代码注入到 IIFE **内部**（紧邻末尾 `})();` 之前）。

### 坐标约定

```
世界坐标：X 右(+)  Y 上(+)  Z 前(+，朝观察者)
立体：中心在原点，轴沿 Y，底面在 y = -H/2
倒放：coneGroup.rotation.z = π
```

六类工程面（法向表达式）：

| 类型 | 名称 | 法向 |
|---|---|---|
| `frontal` | 正平面 ∥V | (0, 0, 1) |
| `fv` | 正垂面 ⊥V | (sin a, cos a, 0) |
| `horiz` | 水平面 ∥H | (0, 1, 0) |
| `pv` | 铅垂面 ⊥H | (cos a, 0, sin a) |
| `lat` | 侧平面 ∥W | (1, 0, 0) |
| `lv` | 侧垂面 ⊥W | (0, cos a, sin a) |

## 二、渲染分层

场景里同时存在多个图层，**点选模式下它们的可见性必须仔细控制**，否则会出现「点一下整块消失」或「什么都没变」：

| 图层 | 点选模式下的行为 | 原因 |
|---|---|---|
| 主立体（`coneF` / `coneB`） | **隐藏** | 由分块网格代替 |
| 分块网格（`cellGroup`） | **显示，`depthTest=true` + `renderOrder=1010+`** | 必须正常参与深度测试，否则远处块/背面会盖住近处块（见 `v33.16`） |
| 自由拼装部件外壳（`partGroup` 中带 `userData.pi` 的） | **隐藏**（含 `userData.piEdge` 的边线） | 与分块网格重合，会干扰点选 |
| 相贯体实体（`cylVis`） | **保持显示**；但"这块材料被隐藏"时不画本体+圆环 | 相贯体是模型的一部分，隐藏会让用户以为"长方体空了"；隐藏后留圆环会像"点了还在" |
| 相贯体轮廓（`hlKeep`） | 保持显示（材料被隐藏时除外） | 是点选模式下相贯体唯一的"把手" |

> **`v33.17` 的关键约束**：`buildParts()` 每次重建都会把 `mesh.visible` 恢复成 `true`。
> 因此"pick 模式下外壳该不该隐藏"这个判定必须**在 `buildParts()` 里也做一遍**
> （`pickShellsHidden()`），否则任何"改模型"动作之后外壳又盖回分块网格上面，
> 用户点了半天觉得"没反应"。

### 踩过的坑

**分块网格与「贯体变实」的相贯体用了同一个橙色 `0xf08c42`**，
而且相贯体是**不透明实体**。两层同色互相遮挡时，用户完全看不出变化——
无论分块算得多对，视觉上都无效。

> **教训**：给「可交互图层」用和「装饰图层」明显不同的颜色，是避免这类问题的结构性办法。

### `v33.16`：为什么分块网格不能 `depthTest=false`

`v33.9` 曾把分块网格与封盖都设成 `depthTest=false`，靠 `renderOrder` 硬压在最上层，
用来盖过「贯体变实」的相贯体。这个做法有严重副作用：

关掉深度测试后，**同一像素由最后绘制的那块决定**，与真实前后关系无关。
分块网格每块都画了 FrontSide + BackSide（背面是深色 `0x4b2a14`），于是

- 远处分块 / 自己的背面会盖住近处分块 → 本该实心的地方透出内壁（用户说的「中空」）；
- 分块交界处出现一条条暗色带（用户说的「莫名阴影」）。

正确做法：**恢复 `depthTest=true`**。
点选模式下相贯体实体本来就会在「它那块材料被隐藏」时整体不画（`cylRegionVisible`），
不需要靠关深度测试来抢层级。

> **教训**：`depthTest=false` 是「画在最上层」的暴力手段，它会让**所有**前后关系失效。
> 只有在「这个物体必须无条件可见、且不参与空间遮挡」时才用（例如点选把手、穿透轮廓线）。

### 三视图相机（`v33.27`）

三视图用**独立的正交相机** `orthoCam`（不用透视相机拉长焦模拟，放大后仍有透视误差）。
`setView(name)` 只认方向名、**保持无状态**；「点第几次翻到对面」的逻辑在按钮层的
`viewButtonClick(prim)` 里。这样测试、`resetView`、切立体等直接调 `setView()` 的地方行为不变。

| 视图 | 相机位置 | `up` | 屏幕右 |
|---|---|---|---|
| front 主视 | `(0,0,+1500)` | `(0,1,0)` | `+X` |
| back 后视 | `(0,0,-1500)` | `(0,1,0)` | `-X` |
| top 俯视 | `(0,+1500,0)` | `(0,0,-1)` | `+X` |
| bottom 仰视 | `(0,-1500,0)` | `(0,0,+1)` | `+X` |
| left 左视 | `(-1500,0,0)` | `(0,1,0)` | `+Z` |
| right 右视 | `(+1500,0,0)` | `(0,1,0)` | `-Z` |

> ★ **对面视图不是"方向取反"就完事**：`up` 必须一起镜像。
> 仰视若沿用俯视的 `(0,0,-1)`，从下往上看时画面会整体旋转 180°，
> 「长对正 / 高平齐 / 宽相等」全乱。

按钮文字是**状态**而不是标签：`markView(name)` 同时负责高亮和文字
（当前在「后视」时，第一个按钮显示「后视」）。
因此 `resetView()` 必须**先 `curView = ""` 再 `markView("")`**，否则会残留「后视」两个字。

## 三、「点选保留部分」的分块系统

这是本项目最复杂的部分。整体流程：

```
采样 → 生成 key → 连通性分割 → 生成裁剪条件 → 渲染 → 点选反查
```

### 3.1 采样

在立体内部与各部件内部撒点：

- 旋转体（圆锥/半球/圆柱）：按半径轮廓分层网格 + 随机点
- 多面体（棱锥/棱台/棱柱）：包围盒网格 + 半空间判定筛选
- 每个启用面的平面：在截面区域内网格采样，沿法向两侧各偏一点
- 自由拼装部件：按部件自身形状撒点（`partBodyPoints`）

> **实验室（`lab`）没有主立体，主立体采样必须直接返回空**（`v33.15`）。
> `SHAPES.lab` 的 `R=1`、`H=1` 只是占位值；若照样跑 `revBodyPoints()`，
> 会在这 2×1×2 的小盒子里撒出 1.8 万个「幻影点」——既让体素桶过密、
> 连通搜索退化成近似 O(n²)（加一个相贯体/面就卡 1.2~1.9 秒），
> 又污染采样间距估计，把连通阈值压到真实间距以下，导致一个部件碎成几十片伪块。
> lab 里真正有意义的采样点只有 `partBodyPoints()`。

### 3.2 生成 key（符号位）

每个采样点按「在每个切割体的哪一侧」生成签名：

```
f<id>:<0|1>  |  c<id>:<0|1|2|3>  |  p<id>:<0|1|2|3>
   面符号位        相贯体四值码         部件四值码
```

**四值码**的含义（相贯体与部件一致）：

| 码 | 含义 |
|---|---|
| `3` | 内部 |
| `0` | 外部、两端之间（从侧面出去） |
| `1` | 外部、正端之外 |
| `2` | 外部、负端之外 |

> **为什么必须四值**：只用「内/外」两位时，**不连通的两个区域会拿到同一个 key**。
> 典型：长方体横穿棱锥，锥顶尖与锥底都在长方体外部，key 完全相同 →
> 点「隐藏锥顶」把锥底一起隐藏 → 用户看到「整个棱锥全没了」。

### 3.3 连通性分割（关键）

四值码仍然不够。反例：圆柱轴沿 Z 时，锥顶尖与锥底都在「两端之间」，
四值码也相同。**符号位无法表达"是否连通"。**

所以需要第三步：把同一 key 的采样点按**空间连通性**用并查集拆分。

```js
// 距离小于阈值的点连起来（体素哈希加速，27 邻域）
// 每个连通分量单独成为一块，key 加 "#n" 后缀
```

**阈值** `voxel = max(2.5, 采样间距 × 1.15)`（采样间距取最近邻距离的中位数）。
`splitByConnectivity` 内部的连接阈值再取 `TH = voxel × 2.2`。

**体素网格边长必须 ≥ 连接阈值**（`v33.15`）：体素桶边长与连接阈值不一致时，
±1 邻域搜索会漏连 —— 两个相距小于阈值、却隔了 2 格边界的点永远搜不到，
本应连通的一大块会被切成几十片伪块。

现在体素桶边长取 `voxel`、阈值取 `voxel × 2.2`，两者并不相等，
所以连通搜索采用**「先快后准」两段式**：

1. 先用 ±1 格（27 桶）快扫求连通分量 —— 绝大多数情况只有 1 个分量，直接返回；
2. **仅当**快扫发现多于一个分量时，才按完整半径 `ceil(TH / voxel)` 重算一遍。

这样单分量的常规场景零额外开销，而真出现多分量时结果与完整半径搜索一致。
体素键用整数（三格坐标压成一个整数）而非字符串拼接，省掉大量哈希开销。

> 注意：**没有「碎片过滤」这一步**。曾经尝试过「把点数很少的小分量并回主分量」，
> 但该改动未经用户确认、且会掩盖真实的连通性问题，已作废并回退 ——
> 现在靠上面的「无漏连」保证不产生伪块，而不是事后丢弃小分量。

> **教训**：用采样点的极值当几何边界，必然削掉边界附近的几何。
> 采样只能用来「判定连通性 / 分组」，不能用来「定义几何范围」。

#### 3.3.1 符号位联合判据（`v33.19`，必读）

**「无漏连」只对"各向同性"的采样点云成立。** `partBodyPoints()` 的采样是各向异性的：

```
径向 3 层（fr = [0.15, 0.55, 0.92]）× 环向 18 × 轴向 15 层
→ 轴向相邻点距 2.43，径向相邻点距 8.8
```

`estimateSampleSpacing` 取**最近邻中位数** = 2.43 → `TH = 2.43×1.15×2.2 ≈ 6.1`。
**径向 8.8 > 6.1，同一层"竖条"之间连不上** → 一个实心圆台被切成 **20 片**，
每片各带一套裁剪平面与背面网格，交界处互相穿插 = 用户看到的"好多条道"。

阈值本身调不出来（要同时跨越 8.8 的采样跨度、又不跨越 7.0 的真实缝隙）。
`v33.19` 的解法是给 `splitByConnectivity()` 加第三个参数 `keyAtFn`（符号位探针），
在纯距离分组之后做一次**几何合并**：

```js
// 两分量最近点连线的中点，是否仍属于同一个符号位区域？
var mid = bp.clone().add(bq).multiplyScalar(0.5);
if(keyAtFn(mid) === key) uni2(roots[ia], roots[ib]);   // 是 → 同一块材料 → 合并
```

- 实心圆台径向上，中点仍在 `||p1:3` 内部 → 合并（20 片 → 1 片）；
- 锥顶尖与锥底被圆柱打穿时，中点落在孔里，符号位是 `|c:3|`（与两者都不同）
  → 保持拆分（3 片，正确）。

**判据从"点距 < 阈值"升级成"两点之间的空间到底是不是同一种材料"。**
有探针时还可以**跳过**「先快后准」的第二趟完整半径重算（±1 快搜的过度拆分由合并兜底），
实测 9.2ms → 5.1ms。

> **教训**：任何"用最近邻中位数定连通阈值"的代码，都要先问一句
> **「这个点云是各向同性的吗」**。不是的话，单一距离阈值必然误拆，
> 必须引入与几何语义（这里是符号位）联合的判据。

#### 3.3.2 分块材质必须跳过自身部件的 `partSpec`（`v33.19`）

`buildCellVis()` 给分块材质设 `setPartSpecs(mat, c.parts)`，
而 `c.parts` 里**包含这块自己所属的部件**（`ownerPart`，`keep=-1`）。
但这一块的几何体**本来就是那个部件的几何**，再让着色器做一次
`abs(q.y) <= d.y` 是冗余的 —— 且在边界上必然出错：
部件顶面正好在 `y = d.y` 上，float32 下 `abs(q.y) <= d.y` 逐像素抖动
→ 顶面被打出一片针孔（实测 127 个像素被误 discard，透出深色背面）。

```js
var ownSpec = c.ownerPart;
var partSpecs = (c.parts || []).filter(function(_, ii){ return ii !== ownSpec; });
```

> **规则**：给分块材质加 `partSpecs` 时，**永远要跳过 `ownerPart`**。

### 3.4 生成裁剪条件

每个 cell 有三类裁剪条件，与渲染时的语义完全一致：

```js
cell = {
  planes: [THREE.Plane...],   // ① 面的半空间 + 连通分量的分割平面
  cyls:   [cylSpec...],       // ② 相贯体（shader discard）
  parts:  [partSpec...],      // ③ 部件体积（shader discard）
  sel:    true|false,         // 是否保留
  pts:    [...],              // 该块的采样点（给点选反查用）
}
```

**分割平面的方向很重要**：
- `top` / `bot` 是「向外保留」，用于 `code 1/2`
- `belowTop` / `aboveBot` 是「向内保留」，用于 `code 0`
- **用反方向会把整块裁没**

**外侧开口不设边界**（`v33.14`）：连通性分割时，只有「相邻分量之间的间隙中点」
才生成分割平面，外侧设为 `±Infinity`。否则用采样点极值当上界，
会削掉锥尖等边界几何。

### 3.5 渲染

```js
// 分块网格：正常参与深度测试（v33.16 起；不要用 depthTest=false）
material.depthTest = true;
mesh.renderOrder = 1010 + (front ? 1 : 0);
```

- 显示的块：`opacity = 1`
- 隐藏的块（幽灵态）：`opacity = 0.06`（正面）/ `0.10`（背面）

> **注意**：幽灵态仍在渲染，颜色变暗但**仍非背景色**。
> 用「像素计数」判断是否隐藏会得到错误结论，必须看颜色/亮度或截图。

#### 封盖（`cellCaps`）的三个必守点（`v33.16` / `v33.17`）

1. **符号位必须走 `parseCellKey()`，不能 `c.key.charAt(j)`**
   —— key 从 v22 起是 `"f12:1,f7:0|c3:1|p6:0"`，按下标取字符拿到的是 `'f'`/`':'`/`,`，
   永远不等于 `"1"`。用错会导致封盖一律按「另一侧」裁剪，画到块的**反侧**，
   屏幕上出现一块深色阴影。
2. **封盖必须带本块自己的 `clippingPlanes`**
   —— 否则封盖是「整个截面」的一大片，直接盖到别的分块上，叠出阴影。
   另外封盖与分块背面网格在剖面处**几乎完全共面**，需沿法向朝被切掉那侧平移
   `0.08mm`（`sgnCap`），否则逐像素 z-fighting 会形成一片橙/深色噪点。
3. **`clipHalfPlane` 的常数项符号（`v33.17`）**
   —— 平面内一点 `p = O + U·u + V·v`，故
   `o2.nv·p - o2.d = cc + a·u + b·v`（`cc = o2.nv·O - o2.d`）。
   本块保留 `n·p-d >= 0`（`plus=true`）时要 `a·u+b·v >= -cc`，
   交给「保留 `a·u+b·v <= c`」的 `clipHalfPlane` 就是 `(-a, -b, +cc)`；
   `plus=false` 时是 `(a, b, -cc)`。
   旧代码写成 `plus ? -cc : cc`（常数项反号，法向项是对的），
   于是几乎每个面都把封盖裁成空多边形 —— 实测用户场景 19 块里 13 块没有封盖，
   隐藏一块之后切口没盖子，**从上方直接看穿到内壁**（用户说的「中空」）。

> 排查口诀：**「中空」先数封盖**。`cells.forEach(c => cellCaps(c, act).length)`
> 只要出现 0，就是裁剪算错，别去改分块采样。

### 3.6 点选反查（`cellAtPoint`）

**最关键的一步**：所有分块网格共用同一份完整立体几何，
靠 `clippingPlanes` + shader discard 在渲染时区分。

但 **`raycaster` 只做几何求交，完全不执行裁剪**。
所以同一屏幕位置会同时命中所有分块，取 `hits[0]` 会拿到**体积最大的那块**
（通常是锥身+锥底）——这就是「点锥顶尖却把整块藏了」的根因。

正确做法：

```js
function cellAtPoint(P){
  // 逐个测试每个 cell 的 planes / cyls / parts
  // 找出真正包含 P 的那一块（与渲染裁剪语义一致）
  // 多个满足时取"离边界最远"的，避免选中临界块
}
```

## 四、相贯线

### 4.1 求交

在部件/相贯体表面采样，找「另一对象内部/外部」的零穿越点。

**`marching squares`**（`v32` 引入）：按网格单元四条边求零穿越点，
同一条边由相邻单元共享（边名做 key），单元内两两连接，鞍点用格心符号消歧。
这样拓扑天然连续，不依赖距离阈值。

> 旧实现用「贪心最近邻 + 固定 3.2mm 阈值」，而表面格距本就有 3~11mm，
> 一条完整的相贯线被切成 10 段各 3 个点的碎线。

**核心已抽成 `surfZeroChains(patches, insideFn)`（`v33.27`）**，两条路径共用一份实现：

```
partSurfZeroChains(ia, fn) → surfZeroChains(partSurfPatches(parts[ia]), fn)   // 部件
penetrationCurves(c)       → surfZeroChains(bodySurfPatches(c), solidOutside) // 主立体 ∩ 相贯体
                            + stitchChains(...)                               //   跨面拼接
```

### 4.1.1 必须铺「全部表面」，而不是只沿母线采样（`v33.27`）

`penetrationCurves()` 原来只沿**相贯体的母线（侧表面）**采样，有两个结构性缺陷：

1. **端面从来没被采样过** → 端盖被切出来的那段交线整段不画；
2. 交线接近**平行于轴向**时，相邻母线的沿轴落差 `dz/du → ∞`，被 `maxGap` 判成断链。

实测（圆锥 + 实体正方体 左右-29 / 高低-22.5 / 前后0 / 棱长29）：
真值 408 个采样点里 **188 个（46%）没画出来**，最远偏 **12.75mm**，两个端盖各缺 84/87。

`bodySurfPatches(c)` 改为铺**全部表面**：

| 截面 | 面 | 网格 |
|---|---|---|
| 圆柱 | 侧面 + 2 个真实端面（极坐标盘） | 96×NV，端面 96×6 |
| 方 / 矩形 | 4 侧面 + 2 端面 | NW×NL、NH×NL，端面 NW×NH |
| 无限贯穿（`len=0`） | **只有侧面** | 96×NV / 4×NW×NL |

两条硬约束：

- **相邻面必须共用同一条边界、同一组分段数**（同样的 NW/NH/NL）。
  这样 marching squares 在边界上求出的零点坐标完全一致，`stitchChains()`
  只需 0.06~0.8mm 容差；两侧分段数不同会差半个格距（~1.5mm），
  又得回头写「最近邻配对」那种不牢靠的启发式。
- **`len=0` 绝对不能铺端面**。`bodyLen()` 返回的 96 只是「为了画得出来」的视觉长度，
  端面在几何上不存在；铺了会在立体内部凭空多出一条环形交线。

修后：缺画 **0/408**、最远 0.29mm、链条 4→1，单次 1.4ms。

### 4.2 曲线分类

用齐次广义特征值法求二次曲线系数，判别式 `Δ = b² - 4ac`：

- `Δ > 0` → 双曲线
- `Δ = 0` → 抛物线
- `Δ < 0` → 椭圆或圆（再用半径是否恒定区分圆弧）
- 拟合残差太大 → 其他曲线

### 4.3 采样要点

- **棱锥必须按「每个侧面单独铺网格」采样**，不能只按棱方向撒点
- **相位必须与 three.js 几何一致**：`CylinderGeometry` 顶点是 `x = R·sin(θ), z = R·cos(θ)`
- 圆柱 / 圆锥 / 圆台要**补端面圆盘采样**，否则交线落在端面上时整段丢失
- **无限贯穿（`len = 0`）的相贯体不要补端面** —— 那段长度只是视觉上的（`bodyLen()` = 96），
  端面在几何上不存在，铺了会凭空多出一条环形交线
- 「显示不全」这类问题必须按**真值覆盖率**测：在全部表面上细采样求真值零点，
  再算每个真值点到画出来的折线的距离（见 `tests/cylcurve.js`）。
  只测「曲线点是否贴在表面上」时，**一个点都不画也会全过**（空集恒真）

## 七、关键教训汇总

1. **符号位只能回答「在哪一侧」，不能回答「是否连通」**
   —— 任何按区域分割的需求，最终都必须落到连通性上。

2. **`raycast` 不执行裁剪**
   —— 分块共用几何时，必须用命中点反查真实归属。

3. **同色会让两层完全混淆**
   —— 可交互图层必须用与装饰层不同的颜色。

4. **采样极值不能当几何边界**
   —— 采样只用于分组/连通性判定，边界要么来自几何本身，要么不设。

5. **`readPixels` 像素计数不能判断「是否隐藏」**
   —— 幽灵态仍在渲染，颜色变暗但非背景色。

6. **模拟测试全绿 ≠ 真实渲染正确**
   —— 前几轮所有 Node 测试都通过，但真实浏览器里问题依旧。
   必须用真实浏览器截图验证视觉层。

### 「显示不全」必须按真值覆盖率测（`v33.27`）

旧 `tests/curves.js` 只断言「曲线点都贴在表面上」「相邻点没跳变」——
**一个点都不画，这两条也全过**（空集恒真）。
缺的整段压根不在结果里，检查「结果里的点好不好」永远发现不了。

正确做法：在**全部表面上**细采样求真值零点，再算每个真值点到画出来的折线的距离
（见 `tests/cylcurve.js`，阈值 1mm）。这一条同时能抓「少画」「画偏」「多画」。
