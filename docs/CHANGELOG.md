# 变更日志

## v33.25（当前版本）

新功能：**贯穿体「深度」+ 孔底封盖**（盲孔）。
顺带修三处隐蔽缺陷，都是排查过程中才暴露出来的。

用户需求原话：
> 「需要给贯穿体加"深度"参数和孔底封盖」

附带问题原话：
> 「添加贯穿圆(正平面，高度35，半径16)后，俯视图看到内部多了一个圆柱」

---

### A. 新功能：深度参数

相贯体面板（「贯穿打孔」）新增 **深度** 输入框：

| 深度 | 行为 |
|---|---|
| `0`（默认） | **打穿**，与之前完全一致 |
| `> 0` | 盲孔，从 **+轴那一侧的孔口** 往材料里钻 |
| `< 0` | 盲孔，从 **-轴那一侧** 的孔口往里钻 |

本质是把「孔内」从**无限长**改成**一段轴向区间** `[t0, t1]`：

```
tA / tB = 两侧孔口在表面上的轴坐标（沿轴步进 + 二分找 insideCone 零点）
depth>0 → t1 = tA, t0 = tA - depth
depth<0 → t0 = tB, t1 = tB + |depth|
再夹到 [min(tA,tB), max(tA,tB)]（钻太深就等于钻穿）
```

这个窗口必须在**四处同时生效**，否则会出现「画面和拾取各说各话」：

| 位置 | 做法 |
|---|---|
| 着色器 `cylDiscard` | `uCylL` 的 `y/z/w` 装窗口；窗口外的片元算材料 |
| `cylMargin` | 窗口外 `m` 变负（= 材料）；分块 / 拾取 / 相贯线共用同一判据 |
| `cylAxisExtent` / `cylCodeAt` / `cylEndPlane` | `halfLen` 换成不对称的 `tTop/tBot` |
| 孔壁几何 | 母线区间夹到窗口里，并在底端补**孔底封盖** |

### B. 孔底封盖

`boreCapGeo()` 在窗口「底」那一端生成圆盘（方孔则是矩形）：

- 圆心落在孔轴线上，沿轴位置 = `tBot`
- 法线朝**孔口方向**，所以从孔口看是受光的正面
- 与孔壁共用 `boreMat`，顶点色统一 0.88（孔底本就该比孔壁略暗）

像素判据（正视、过孔心）：

| 深度 | 孔内颜色 | 含义 |
|---|---|---|
| 0 | `#0e1420` | 背景色，贯穿孔物理正确 |
| 22 | `#72401a` | 孔底封盖，均匀一致，不再透出 `#4b2a14` 背壳 |

### C. 关于「俯视图内部多了一个圆柱」：不是 bug

用户参数是 **高低 = 35**，而圆柱默认 `H = 70`，**顶面正好在 y = +35**。
也就是说**孔轴贴在顶面上**，挖出来的不是通孔而是一条**半开槽**；
俯视看到的「内部圆柱」正是这条槽**两侧的筒壁**。

三种方式验证：

1. `probe_mouth.js`：孔壁顶点精确落在表面上（`worst = 0`），无越界；
2. 把高低改成 0：俯视是正常通孔，没有「内部圆柱」；
3. 逐像素分层探针：那片区域每个像素都来自 `boreGroup` 的孔壁网格，
   不存在任何多出来的几何体。

建议用法：

- 竖直通孔 → 用「**水平面**」型贯穿圆（轴沿 Y），不要用正平面；
- 侧向通孔 → 正平面 / 侧平面，但**高低要落在 (-35, +35) 之间**；
- 想打一半 → 直接用「深度」，不必再靠贴边模拟。

### D. 三处隐蔽缺陷

#### D1. GLSL 里不能链式取 uniform 数组成员

```glsl
// 错：部分 GLSL 编译器直接编译失败
if(uCylL[i].w > 0.5 && (axl < uCylL[i].y || axl > uCylL[i].z)) ins = false;

// 对：先整个取出来
vec4 L4 = uCylL[i];
if(L4.w > 0.5 && (axl < L4.y || axl > L4.z)) ins = false;
```

**症状极具误导性**：不报错退出，而是**整个材质编译失败 → 孔壁整层静默消失**。
`renderer.debug.onShaderError` 在无头环境里也抓不到（`__SHERR = []`）。
最后是靠「把 boreGroup 整体平移到 x=60 就能看见」才定位到是材质编译问题。

#### D2. 自建 BufferGeometry 必须显式 `computeBoundingSphere()`

three.js 的包围球是**渲染时惰性计算**的，而视锥剔除判定发生在它还是 `null` 的时候
→ 整块封盖被当成「不在视锥内」直接跳过，**永远不渲染**。
`computeVertexNormals()` **不会**顺手算包围球。

表现为「几何明明在，就是不画」，极难查。

#### D3. 改参数不重建孔壁

`buildBoreVis()` 原来只在 `refresh()` 和 `buildCellVis()` 里调用；
但相贯体输入框的 `input` 事件走的是 `buildCylVis(); applyClipping();` —— **不重建孔壁**。
于是改了「深度」之后，孔壁几何还是旧的贯穿版（画面「深度没反应」）。

修法：7 处「改相贯体参数」的 input 处理器后面都补 `try{ buildBoreVis(); }catch(_){ }`。

## v33.19

修用户反馈的三条（第三条是补充说明的）：

1. **模型拼装里的 3D 模型上面有好多条道**（表面一条条竖向深色缝 + 顶面一片麻点）；
2. **模型拼装里的 3D 模型拖动时，有时候会卡**；
3. **模型拼装里加出来的 3D 模型自动是橙色的，点「拼装变实」也不会变成青色**。

---

### A. 表面「好多条道」：两个独立根因

#### A1. 一个实心部件被自己的采样层切成 20 片

`partBodyPoints()` 的采样是**各向异性**的：

```
径向 3 层（fr = [0.15, 0.55, 0.92]）× 环向 18 × 轴向 15 层
→ 轴向相邻点距 2.43
→ 径向相邻点距 8.8（fr 层之间的跨度）
```

而连通阈值 = `estimateSampleSpacing()`（最近邻中位数）× 1.15 × 2.2 ≈ **6.1**。
**径向 8.8 > 6.1，同一层的"竖条"之间连不上** → 一个实心圆台被切成 **20 片**。
每片各自带一套裁剪平面 + 自己的背面网格，交界处互相穿插 →
屏幕上就是一条条深色缝。

实测：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| lab + 圆台 | 20 片 | **1 片** |
| lab + 球 | 3 片 | **1 片** |
| 真实打穿（pyr3 + 沿 Z 圆柱 r=13） | 3 片 | 3 片（仍正确拆分） |

修复：`splitByConnectivity()` 增加第三个参数 `keyAtFn`（符号位探针），
在纯距离分组之后做**几何合并** —— 取两分量最近点连线的中点，
若它仍属于同一个符号位区域，说明两者之间是连续的同一种材料，合并：

```js
var mid = bp.clone().add(bq).multiplyScalar(0.5);
if(keyAtFn(mid) === key) uni2(roots[ia], roots[ib]);
```

> **为什么不去调阈值**：阈值要同时满足"跨越各向异性采样（径向 8.8）"
> 和"不跨越真实缝隙（7.0）"，这两个要求在圆台上直接冲突，调不出来。
> 必须引入**符号位与几何的联合判据**。

#### A2. 分块网格对自己所属部件又做了一次"内部判定"

`buildCellVis()` 给分块材质设 `setPartSpecs(mat, c.parts)`，
而 `c.parts` 里**包含这块自己所属的部件**（`ownerPart`，`keep=-1` 保留内部）。
可这一块的几何体**本来就是那个部件的几何**，再让着色器做一次
`abs(q.y) <= d.y` 是完全冗余的 —— 但它在边界上必然出错：

```
圆台顶面正好在 y = d.y 上 → float32 下 `abs(q.y) <= d.y` 逐像素抖动
→ 顶面被打出一片针孔（实测 127 个像素被误 discard）
```

修复：跳过自己所属部件的那条 spec（几何上等价，去掉边界抖动）：

```js
var ownSpec = c.ownerPart;
var partSpecs = (c.parts || []).filter(function(_, ii){ return ii !== ownSpec; });
```

修复后（软光栅逐像素统计）：

| 指标 | v33.18 | v33.19 |
|---|---|---|
| 深色背面像素（圆台顶面） | 127 | **0** |
| 相邻像素跨 mesh 转移 | 1316 | **0** |

### B. 拖动卡顿：一次 pointermove 触发两次全量重建

v33.17 在 `buildParts()` 末尾加了 `if(mode === "pick") cellsDirty = true;`，
而 `partDrag` 的 pointermove 分支当时写的是：

```js
if(mode === "pick"){ rebuildCells(); buildCellVis(); cellsDirty = false; }  // 先清位
try{ buildParts(); }catch(_){ }                                            // 又置位！
```

顺序反了 —— `buildParts()` 把刚清掉的 `cellsDirty` 又置回 true，
**渲染循环那一帧再完整重建一遍**。实测一次 pointermove = `rebuildCells()` × 2。

修复：调换顺序（先 `buildParts()` 置位，再统一重建并清位）。
实测 `rebuildsInPointermove` 从 **2 → 1**。

顺带的性能优化（都在拖动路径上）：

| 函数 | 优化 | 实测 |
|---|---|---|
| `estimateSampleSpacing` | `P.distanceTo()` → 纯标量平方距离；采样 400→200 | **16.4ms → 0.2ms** |
| `splitByConnectivity` 合并层 | `distanceToSquared()` → 标量平方 | 少量 |
| `buildComponents` 完整半径重算 | 有 `keyAtFn` 探针时跳过（±1 快搜的过度拆分由探针合并兜底） | 9.2ms → 5.1ms |

单次拖动（`buildParts + rebuildCells + buildCellVis`）实测 **34ms → 19ms**（node，无 GPU）。

### C. 拼装部件自动橙色 / 变实不变青

点选模式下部件外壳被隐藏（`pickShellsHidden`），屏幕上画的是**分块网格**，
而 `buildCellVis()` 里分块的颜色是**写死的** `0xf08c42`（模型橙）。于是：

- 新加的拼装部件一进点选模式就变橙色；
- 按「拼装变实」只改 `partMaterials()`（**外壳**材质），外壳是隐藏的
  → 屏幕上一点变化都没有。

修复：属于拼装部件的分块（`c.ownerPart != null`）沿用部件自己的配色：

| 状态 | 分块正面颜色 |
|---|---|
| v33.18 加出来 | `f08c42`（模型橙，错） |
| v33.19 默认 | `8fd8ff`（半透明青蓝，与 all 模式一致） |
| v33.19 按「拼装变实」 | `12d6c8`（青色实体，与外壳同色） |

主立体的分块**仍然保持模型橙**（那是"被切开的立体"，橙色是对的），
回归里专门加了断言防止部件配色污染主立体。
并且「拼装变实」按钮在点选模式下额外重建一次分块（否则只改了隐藏的外壳）。

## v33.18

两件事：修 v33.17 里自己引入的一个下标错位缺陷；把两个"长期红"的测试修对。
（均为自查发现，用户未反馈。**产品代码只改了第一件。**）

### A. 产品缺陷：`cylVis` 的下标对应 `cyls`，不是 `activeCyls()`

v33.17 给 `tapPick()` 加"相贯体伸出段也能点"时，写成：

```js
var cvs = activeCyls();
...
var chBest = chits[0], cc2 = cvs[chBest.ci];   // ← chBest.ci 是 cylVis 的下标
```

但 `cylVis` 是 `buildCylVis()` 里 `cyls.forEach(function(c, i){...})` 建的 ——
下标对应**全部** `cyls`；而 `activeCyls()` 只含"启用"的、且按 `_id` 重排过。

后果：只要有一个相贯体被停用，下标就整体错位 ——
**点 A 的伸出段会藏掉 B 的材料**，或者因为 `hole` 判断落在别的对象上而完全没反应。

实测（停用小圆柱 r=6、只留大圆柱 r=14，点大圆柱伸出段）：

```
v33.17:  activeCyls()[0].r = 14，但 cylVis[0] 画的是 r = 6  → 错位
v33.18:  命中段 = c14:3（大圆柱自己的 _id）                 → 正确
```

修复：命中判定改用 `cyls` 索引（并显式判 `cc2.on && !cc2.hole`），
算 key 仍用 `activeCyls()`（`cellKeyAt` 的 key 按启用集合拼，语义不同，不能混用）。

### B. 测试缺陷：两个套件长期误报（**不是产品问题**）

`regions.js` 与 `cellgeo.js` 从 v33.15 起一直"红"，交接文档里记作"既有失败"。
本次查清：**它们报的是测试自己的 bug，产品一直是好的。**

#### B1. 裸 key 与带后缀 key 直接比较

连通性分割会给 key 加 `#n` 后缀（`"||p1:0#0"`、`"||p1:0#1"`），
而 `cellKeyAt()` 只产出**裸 key**（`"||p1:0"`）。两个测试都写成：

```js
if(cellKeyAt(P,act,cs,ps) === c.key)   // 带后缀的块永远匹配不上
```

→ 带后缀的块 `ownTotal = 0`（`coverage = 0%`），
且所有同符号位的点全被算成 `foreign`（"越界覆盖"）。

修复：两边都剥掉 `#n` 再比。

#### B2. 把"分量"当成"整个区域"来要求 100%

同一个符号位 key 被拆成多个连通分量后，**每个分量只覆盖共享区域的一部分**。
`cellgeo.js` 原来要求 `every(coverage >= 99.9)`，这是不可能满足的。

修复：按"剥后缀后的 key"分组，要求**同组所有分量的并集覆盖 100%**。
实测（A 场景，正三棱锥 + 默认长方体）：

```
[group] {"key":"||p1:0","cells":3,"pts":103,"cover":100}   ← 3 个分量合起来 100%
[group] {"key":"||p1:1","cells":1,"pts":1573,"cover":100}
[group] {"key":"||p1:2","cells":1,"pts":1716,"cover":100}
[group] {"key":"||p1:3","cells":1,"pts":6615,"cover":100}
```

#### B3. 修正后仍能抓真 bug（反证过）

把 `cellCaps` 的常数项符号改回错的（v33.16 状态），用户场景立刻
**19 块里 13 块无封盖** → `pickfix.js` 的"每块都有封盖"FAIL。
说明这些测试不是"改成永远绿"，仍然有约束力。

## v33.17

修复用户反馈的三个「点选保留部分」问题：

1. **内部仍然中空** —— 切完之后能从上面直接看到内部；
2. **增加圆柱后（模型拼装 / 相贯体都算），用「点选保留部分」点该圆柱，突出来的那截不消失**；
3. **模型拼装的模型，移动后点撤销，移动后的 3D 模型仍存在**，
   而且有时会变成与「贯体变实」相同的颜色、有时有很多噪点、并且无法删除。

### 根因 1：封盖的常数项符号写反了（"中空"）

`cellCaps()` 用 `clipHalfPlane(poly, plus?-a:a, plus?-b:b, plus?-cc:cc)` 把截面多边形裁到本块那一侧。
平面内一点 `p = O + U·u + V·v`，所以

```
o2.nv·p - o2.d = cc + a·u + b·v        (cc = o2.nv·O - o2.d)
```

本块保留 `n·p-d >= 0`（`plus=true`）→ 要 `a·u+b·v >= -cc`，
交给「保留 `a·u+b·v <= c`」的 `clipHalfPlane` 应当是 **`(-a, -b, +cc)`**；
`plus=false` 时是 **`(a, b, -cc)`**。

旧代码把**常数项**写成了 `plus ? -cc : cc`（法向项是对的）→ 几乎每个面都把封盖裁成空多边形。
**实测用户场景（圆柱+圆柱部件+5面）19 块里有 13 块生不出封盖**，
隐藏一块之后切口没有盖子，从上面直接看穿到内壁 = 用户说的「中空」。

修复：`plus?cc:-cc`。修好后 19/19 块都有封盖。

> 这条**只有看俯视图才会发现** —— 侧视时切口多被自己的侧面挡住，
> 封盖缺失看起来只是「有点暗」。验收必须加俯视/仰视。

### 根因 2：`buildParts()` 把部件外壳重新点亮（"点突出来的圆柱不消失"）

`v33.3` 起，pick 模式下部件外壳（`partGroup` 里带 `userData.pi` 的 Mesh，opacity 0.55）
要隐藏，让分块网格（`cellGroup`）当主角。这个判定写在 `buildCellVis()` 里，只在 `refresh()` 时跑一次。

但 `buildParts()` 每次重建都会 `new THREE.Mesh(...)`，`visible` 默认 `true`。
于是任何「改模型」的动作（拖动、改尺寸、加/删部件、切拼装变实…）之后，
外壳又盖回分块网格上面：**分块明明已经隐藏了，屏幕上那块圆柱看起来一点没变。**

修复：
- 抽出 `pickShellsHidden()`，`buildCellVis()` 与 `buildParts()` 共用同一份判定；
- 部件**边线**（`LineSegments`）用单独的 `userData.piEdge` 标记，一起隐藏
  （不能复用 `userData.pi` —— 那是"本体 Mesh"的标记，拾取和测试都靠它区分）。

### 根因 2b：相贯体伸出主立体之外的那截，根本点不到

分块几何用的是主立体 `geo`，相贯体伸出主立体外的部分被裁得干干净净
（实测 `cellGroupHits = 0`）。点它时 `tapPick()` 一个候选都收不到 → 直接 `return` → 「点了没反应」。

修复：`tapPick()` 增加一路候选 —— 对相贯体自己的实体网格（`CylinderGeometry` / `BoxGeometry`）求交，
再沿射线往里挪一点求 `cellKeyAt`（命中点正好在相贯体表面上，`cylCodeAt` 会判成"恰在表面"返回 null），
得到"这块材料"对应的 cell 一起切换。求交**不看 `visible`**，保证藏了还能点回来。

另外：材料被隐藏后，两圈端面圆环（`hlKeep`）不该还飘在半空 ——
`buildCylVis()` 里对 `bodyHidden` 的相贯体把 `hlDecor` 全部收掉，
且在 `setCylHighlightVisible()` **之后**再压一次（那个函数会按 `hlKeep` 重新点亮）。

### 根因 3：`buildParts()` 没让分块跟着重算（"移动后残留/变色/噪点/删不掉"）

部件的**位置/尺寸/方向**都参与分块（cell 的裁剪平面与 `partSpec` 都按 `parts` 算），
但 `buildParts()` 只重建了部件外壳，**没有让分块重算**。

于是拖动部件之后：分块网格用的是"新位置"的部件几何（`partGeoOf` + `partMatrix`），
却配着"旧位置"的裁剪平面与部件体积规格 —— 两者错位，屏幕上留下一块
橙色的（`0xf08c42` = 分块正面，正是用户说的「贯体变实的颜色」）位置错误、
边缘全是噪点、删也删不掉的残影。

`cylDrag` 分支早就有 `cellsDirty = true`，`partDrag` / 面板输入 / 增删部件都没有。

修复：
- `buildParts()` 末尾 `if(mode === "pick") cellsDirty = true;`
- `partDrag` 的 `pointermove` 分支里立即 `rebuildCells() + buildCellVis()`，拖动中就跟手；
- `endDrag()` 的 `partDrag` 分支同样立即重建，保证"松手"的同一帧对齐。

## v33.16

修复「点选保留部分」模式下的两个显示缺陷：
**① 模型有些中空、很多实体的地方没显现（要求模型是实体）；② 加面之后某个地方有莫名的阴影。**

### 根因 1：「中空」= 分块网格关了深度测试

`v33.9` 为了让「贯体变实」的不透明相贯体不挡住分块网格，
把分块网格和封盖都设成 `depthTest=false`，靠 `renderOrder` 硬压在最上层。

但关掉深度测试后，**同一像素由最后绘制的那块决定**，与真实前后关系无关。
分块网格每块都画 FrontSide + BackSide（背面是深色 `0x4b2a14`），于是：

- 远处分块 / 自己的背面盖住近处分块 → 本该实心的位置透出内壁 = 用户看到的「中空」；
- 分块交界处出现一条条暗色带 = 用户看到的「阴影」。

### 根因 2：「阴影」= 封盖取符号位取错了

`cellCaps()` 里用 `c.key.charAt(j) === "1"` 判断第 j 个面在哪一侧 ——
这是 v22 以前 key 还是纯 `"101"` 字符串时的写法。v22 起 key 变成
`"f12:1,f7:0|c3:1|p6:0"`，按下标取到的字符是 `'f'` / `':'` / `','`，
**永远不等于 `"1"`**：

- 所有 `plus` 都被判成 `false` → 封盖一律按「另一侧」裁剪，画到块的**反侧**；
- 封盖还没带本块自己的 `clippingPlanes` → 是「整个截面」一大片，直接盖到别的分块上。

两者叠加，就是那块「莫名的阴影」。

### 修复

1. `buildCellVis()`：分块网格与封盖**恢复 `depthTest = true`**（不再靠关深度测试抢层级）
2. `cellCaps()`：符号位改走 `parseCellKey().fm[o2.id]`
   （保留对 `buildInterCaps` 传进来的 `"111…"` 伪 key 的兼容）
3. 封盖材质补上 `clippingPlanes: c.planes`，只画本块那一侧
4. 封盖多边形沿法向朝「被切掉那侧」平移 `0.08mm`，消除与分块背面网格的共面 z-fighting

### 实测（Edge headless，真实 `refresh()` 路径）

同一场景（圆柱卡片 + 1 个圆柱部件 + 5 个面 + 点选模式）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 与「显示全部」单实体的像素差异（舞台区） | 6.17% | **1.77%** |
| 同上，2 面场景 | 4.16% | **1.40%** |
| 暗色伪影（占实体像素） | 明显成片 | 仅剩轮廓/装饰 |

隐藏一块后剖面上不再出现橙/深色噪点（封盖正常封住切口）。

## v33.15

修复「实验室 · 自由拼装」里增加相贯体/面时卡顿 1.2~1.9 秒的问题。

### 根因

`SHAPES.lab` 是空白实验室（`R=1, H=1`），本来**没有主立体**，
但 `samplePoints()` 没有判断模式，仍然跑 `revBodyPoints()` ——
于是它在 2×1×2 的小盒子里撒出 **18,011 个「幻影点」**。这些点带来两个后果：

1. `splitByConnectivity` 的体素桶极密，27 邻域扫描退化成近似 O(n²)
   → 加一个相贯体/面就卡 1.2~1.9 秒；
2. 它们污染 `estimateSampleSpacing`，把采样间距从 ~3.1 拉低到 ~0.12，
   连通阈值随之降到 2.5（低于部件点云真实的 ~3.06 间距）
   → **一个圆柱部件被碎成 51 片伪块**。

这也解释了用户观察到的两个对照现象：
- 加「模型拼装」部件不卡 —— `addPart()` 只调 `buildParts()`，不经过 `refresh()`；
- 其他功能卡片不卡 —— 它们有真立体，采样点摊得开、体素桶稀疏。

### 修复

- **`samplePoints()`**：`if(SHAPES[shape].lab) return [];`
  实验室不再采主立体点（lab 里真正有意义的采样点只有 `partBodyPoints()`）
- **`splitByConnectivity()`**：
  - 体素键由字符串拼接改为整数键（三格坐标压成一个整数），
    省掉 1.8 万点 × 27 次查询的字符串哈希开销
  - 连通搜索改「先快后准」两段式：先用 ±1 格快扫，
    仅当发现多于一个分量时才按完整半径 `ceil(TH/voxel)` 复核。
    既保住单分量场景的零额外开销，又修掉「阈值比格子大、只搜 ±1 格
    导致漏连、把一大块切成几十片伪块」的既有缺陷

### 实测

| 操作（实验室 · 点选模式） | 修复前 | 修复后 |
|---|---|---|
| 加相贯体 | 1,262 ~ 1,282 ms | **19 ~ 47 ms** |
| 加面 | 1,819 ~ 1,902 ms | **7 ~ 38 ms** |

其他卡片未变慢，反而略快（如圆锥+相贯体 157→112 ms）。
实验室分块数从错误的 63 修正为 4（伪块消失）。

真实浏览器（Edge headless）复测：加相贯体 **1262.6 ms → 19.1 ms**，
加面 **1902.3 ms → 7.3 ms**；同场景前后截图像素差异仅 **0.26%**，
且差异只来自状态文字（`cells=63`→`4`），几何渲染一致。

### 说明

`tests/regions.js` 与 `tests/cellgeo.js` 各有一个失败，
是**本版之前就存在**的既有问题（穷举法把同一符号位区域算 1 块、
连通性分割拆成 2 块，导致「穷举数 7 ≠ 分块数 8」），与本次改动无关。

## v33

分块语义重写 + 相贯线精度 + 性能优化。这是一个较大的重构版本。

### 分块系统（「点选保留部分」）

- **自由拼装部件参与分块**：部件体积进入着色器裁剪（`uPartC/Q/D/K`），
  部件可被面/相贯体/其它部件切成子区域
- **部件四值码**（`0` 侧外 / `1` 顶外 / `2` 底外 / `3` 内部）：
  修掉「长方体横穿棱锥时，隐藏锥顶尖却连锥底一起隐藏」
- **相贯体四值码**：同上，修掉相贯体裁切时的同类问题
- **连通性分割**：同一符号位下不连通的区域用并查集拆成独立块
  （符号位无法表达「是否连通」，这是本版最核心的修复）
- **分割平面**：用相邻分量间隙中点切分，外侧开口不设边界（不削掉锥尖）
- **`cellAtPoint(P)`**：射线检测不执行裁剪，必须用命中点反查真实归属的 cell

### 几何判定修正

- **`insideSolidWorld` 多面体判定**：原来用极坐标半径公式，
  但角度取 `atan2(z,x)` 而 three.js 顶点是 `x=R·sin, z=R·cos`，差 90° 相位。
  实测约 8.9% 采样点内外判错 → 改用半空间判定，误差降为 0%
- **正三棱锥内部判定**：原来用 `x²+z² ≤ r²`（这是圆锥），
  实际截面是三角形 → 改用真三角形判定
- **默认摆放方向**：`addPart` 默认类型从 `frontal`（水平）改为 `horiz`（竖直）

### 相贯线

- **棱锥表面采样**：原来只在 3 条棱中点方向各撒 1 列点，且相位用 `cos/sin`
  而几何体用 `sin/cos`，整块转 90° → 改为每个侧面单独铺网格，相位对齐。
  曲线点到表面偏差 **5.13mm → 0.00mm**
- **端面采样**：圆柱/圆锥/圆台补端面圆盘，修掉交线落在端面上时整段丢失

### 性能

- `selInherit` 记忆化 + 递归深度 4→2 + 命中即返回：**17.3s → 0.67s**
- `partInvOf` 缓存逆矩阵（按参数签名失效）
- `partBoundaryDist` 廉价距离粗筛
- 体素哈希加速连通性邻域查询

### 视觉

- 分块网格 `depthTest=false` + `renderOrder=1010+`，永远画在最上层
  （否则被同色的「贯体变实」相贯体盖住，点了看不出变化）
- 隐藏态 `opacity` 0.1 → 0.06，让「变暗」更明确
- 相贯体轮廓设 `hlKeep`，点选模式下保持可见（是相贯体唯一的把手）

### 测试

- 新增 `cellgeo.js`（分块裁剪互斥完备）
- 新增 `cylpick.js`（相贯体裁切点选）
- 新增 `tintpick.js`（贯体变实 + 点选遮挡）
- 新增 `eventflow.js`（真实 DOM 事件流，pointerdown@canvas → pointerup@window）
- 新增 `verify_geom.py`（纯 Python 独立几何验证）
- 新增 `test3/regions.js`（第二套独立 harness，union-find 计区域）
